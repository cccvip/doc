# Java 技术文档写作 SOP（javadoop 风格）

> 本文规定本仓库技术文档（尤其 `Java/` 下源码分析类）的写作规范。
> 与 [_review-checklist.md](./_review-checklist.md) 配套：那份管"改错"，这份管"怎么写"。
> 风格样板见 [基本/线程池.md](./基本/线程池.md)，原文参考 [javadoop.com](https://javadoop.com/)。

## 0. 一句话原则

**简单内容，简单说；涉及源码，抛砖引玉。**

- 概念、结论、能几句话讲清的——几句话讲清，不硬撑篇幅；
- 源码——只贴能说明问题的关键方法，逐行加中文注释，把难点讲透；
- 又长又少用的方法——明确写"限于篇幅，读者自行翻源码"，并交代"接着该看哪儿"。

## 1. javadoop 风格的六个特征

写之前先记住这六点，它们就是这套风格的全部：

1. **叙事化**：用"我 / 我们 / 读者"口语化地讲，先抛问题或结论，再展开，不堆术语；
2. **源码逐行 + 中文注释**：贴关键源码，在行内用 `//` 写中文解释（所谓"一行一行源码分析"）；
3. **抛砖引玉**：核心讲透，次要方法明确省略并给出下一步线索；
4. **引用块放旁注**：`>` 用来放 Tips、补充、注意事项、读者反馈；
5. **结尾小结**：常以"我一向不太喜欢写总结……"开头，为面试读者列成编号清单；
6. **简单内容简单说**：小主题几句话说清就收，不注水。

## 2. 标准骨架

新写 / 重写一篇文档，套这个骨架（可按主题增删小节，但顺序基本不变）：

```text
（开场引子：2~4 句。为什么写这篇 + 本文思路 + 给面试读者的提示）

# 总览            一句话核心结论（加粗）+ 结构/继承关系 + 必须先掌握的概念
# 核心原理 / 关键概念
# 源码分析         关键方法逐个贴出、逐行注释
# 实战 / 常见坑
# 小结             面试清单
# 参考             外部权威链接 + javadoop 对应文章
```

> 标题一律用**中文叙事标题**，不要再用 `# what` / `# how` / `# other` 这种英文骨架标题；结尾统一用 `# 小结`（取代原来的"八股速查 / 高频八股"）。

## 3. 各节写法细则

### 3.1 开场引子

2~4 句，第一人称，交代三件事：为什么写、本文思路、怎么读。

```markdown
我相信大家都看过不少关于 XX 的文章，而且它基本上是面试必问的。
如果你看完很多篇还是一知半解，那希望本文能让你真正搞明白它。
本文会把 XX 的 YY 方法一行一行过一遍；如果只为面试，可以直接滑到最后的**小结**。
```

### 3.2 总览

- 用**一句话 + 加粗**给出核心结论，例如"ThreadPoolExecutor 就是「核心线程 + 任务队列 + 最大线程 + 拒绝策略」的组合"；
- 类之间的继承 / 协作关系，用一段 ```` ```text ```` 图或表格画出来；
- 把"先掌握这几个概念，否则后面会绕晕"的话说在前头。

### 3.3 源码分析（抛砖引玉的落点）

这是 javadoop 风格的核心，规矩最多：

- **只贴关键方法**，不要整类粘贴；无关的方法甚至不要出现；
- 每段源码**上方一句**说明"这是什么、为什么看它"；
- 关键行**行内**加 `// 中文注释`，把 Doug Lea 的"小九九"点出来；
- 保留 JDK 原始签名，注释用中文，不要擅自改名；
- 冗长 / 少用的方法，一句话交代 + 明确省略：

```markdown
`addWorkerFailed` 没什么内容，就是把 worker 从集合里删掉、线程数 -1，**留给读者自己看**。

> 这个方法负责善后，限于篇幅不展开，读者自行翻源码。
```

- 代码块**必须标语言**：`java` / `text` / `xml` / `yaml` / `shell`。

### 3.4 概念讲解（"简单内容简单说"）

- 3~6 句说清，能用类比就用类比；
- 需要对比的，用表格，别写成大段文字；
- 不追求"面面俱到"，抓住那条主线即可。

### 3.5 实战 / 常见坑

- **必须承上启下**：实战小节要显式呼应前文讲过的机制，说明"前面读的东西在这里是怎么用的"，**不能另起炉灶讲一个新主题**；
- 开头用一两句过渡，把话题从原理 / 源码引到应用；结尾可一句"启下"，自然带出下一节（如常见坑）；
- 场景导向：先给场景，再给可复制的配置或代码模板；
- 若涉及框架源码，最好**逐条对照**前文讲过的参数 / 方法，点明"它没发明新东西，只是重配了一遍"；
- 与本主题无关的框架细节（调参、配置），压成 `>` 旁注或一句话带过，别喧宾夺主；
- 坑用**编号列表**，一条一句，直给结论。

### 3.6 小结

- 复刻口吻："我一向不太喜欢写总结，因为该说的正文里都说了……不过考虑到很多读者是冲着面试来的"；
- 用**编号 Q&A**，每题一句到两句，服务面试复习。

### 3.7 参考

- 外部权威资料（官方文档、经典文章）；
- 若对应 javadoop 有同类文章，一并列出。

## 4. 语言与格式规范

| 项 | 规范 |
|---|---|
| 人称 | 用"我 / 我们 / 读者"，不用"用户 / 你" |
| 关键词 | 首次出现给全称或英文，关键结论**加粗** |
| 旁注 | 用 `>` 引用块放 Tips、补充、注意事项 |
| 中英文之间 | 加空格，如 `核心线程数 corePoolSize` |
| 段落 | 短段落，多用列表 |
| 代码块 | 必须标语言标签 |
| 标题 | 中文叙事标题，`#` 一级、`##` 二级，不跳级 |

## 5. 反面清单（不要这么做）

- ❌ 整段粘贴 JDK 源码却不加任何注释；
- ❌ 罗列一堆注解 / 参数 / 方法名而不解释它们为什么存在；
- ❌ 只堆结论、没有推导，读者"知其然不知其所以然"；
- ❌ 浅内容硬凑篇幅（靠水词、重复），或深内容一笔带过；
- ❌ "实战"小节与前文脱节、另起炉灶，读者看不出它和原理的关系；
- ❌ 示例缺关键前提导致跑不通（如注解漏 `@Retention(RUNTIME)`、`getInstance` 漏 `static`）——这一点对照 [_review-checklist.md](./_review-checklist.md) 第 2 批；
- ❌ 用 `# what` / `# how` / `# other` 当正文标题；
- ❌ 结尾没有小结，或小结只是正文的复制粘贴。

## 6. 交付前检查清单

- [ ] 开场交代了本文思路和阅读建议；
- [ ] 关键结论已加粗，总览给了结构图 / 表格；
- [ ] 所有源码块都逐行加了中文注释；
- [ ] 次要方法有明确的"抛砖引玉"省略说明；
- [ ] 简单内容没有注水，难点讲透；
- [ ] "实战"小节承上启下，显式呼应了前文机制，没有另起炉灶；
- [ ] 代码块语言标签正确，示例可运行；
- [ ] `>` 引用块用在了旁注 / Tips 上；
- [ ] 有编号式 `# 小结`；
- [ ] 有 `# 参考`，并链到 javadoop 对应文章（若有）；
- [ ] 中英文间空格、标题层级无误。
