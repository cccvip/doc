## 一、概念与定位

### Spring、Spring MVC、Spring Boot 是什么关系

Spring 是底层框架，最核心的是 IoC 和 AOP；Spring MVC 是它里面负责 Web 的一个模块；Spring Boot 是搭在 Spring 之上的脚手架。Boot 不动 Spring 的核心，只是把配置、依赖、内嵌服务器都提前备好，让你少写 XML 和样板代码。要写 Web 程序，用的还是 Spring MVC，只是 Boot 帮你配好了。

### Spring Boot 的核心优势是什么

省配置，靠自动配置加默认值；省依赖管理，靠 starter 把一组相关依赖打包、统一版本；内嵌服务器，打成 jar 直接 `java -jar` 就能跑，不用先装 Tomcat；再就是 Actuator 提供的准生产监控。

### Spring Boot 和 Spring 的区别

严格说是包含关系——Boot 是 Spring 的一种使用方式。Spring 更底层，得自己搭配置；Boot 用"约定优于配置"把大量样板省掉，还内置了服务器，让应用可以独立运行。面试时把"约定优于配置"落到具体例子上更有说服力，比如引入 web starter 就默认给你配好 Tomcat 和 Spring MVC。

### 常见 starter 有哪些

web（Spring MVC + Tomcat + Jackson）、data-jpa（JPA + Hibernate）、security、actuator、test、validation。starter 本身通常是个只负责引依赖的 POM，真正的自动配置在对应的 autoconfigure 模块里。细节见 [starter.md](starter.md)。

## 二、启动流程

### Spring Boot 的启动流程

一句话：`main` 调用 `SpringApplication.run`，准备 `Environment`，创建 `ApplicationContext`，把主配置类登记成 BeanDefinition，然后 `refresh`——装配、创建 Bean、启动内嵌服务器都在这一步，最后执行 Runner 并发 `ApplicationReadyEvent`。

面试要主动点出关键边界：主配置类在 `prepareContext` 阶段只是被登记，注解一个都还没解析，真正解析要等 `refresh`。展开见 [启动流程.md](启动流程.md)。

### new SpringApplication 阶段做了什么

三件事。按 classpath 推断应用类型，是 Servlet、响应式还是非 Web；从 `spring.factories` 加载初始化器和监听器；用调用栈找到 main 方法所在的主类。应用类型决定了后面建哪种容器、要不要起服务器。

### 启动过程中有哪些事件，顺序如何

`ApplicationStartingEvent` → `ApplicationEnvironmentPreparedEvent`（此时配置已加载）→ `ApplicationContextInitializedEvent` → `ApplicationPreparedEvent`（主配置类已登记）→ `ContextRefreshedEvent`（刷新完成，内嵌服务器此时已启动）→ `ApplicationStartedEvent`（Runner 之前）→ `ApplicationReadyEvent`（Runner 之后，应用就绪）。中途失败会有 `ApplicationFailedEvent`。

### ApplicationRunner 和 CommandLineRunner 的区别

都在 `refresh` 完成后执行，唯一区别是入参：`ApplicationRunner` 拿到解析过的 `ApplicationArguments`，`CommandLineRunner` 拿到原始 `String[]`。多个之间用 `@Order` 排序。适合预热缓存、初始化数据。

### @PostConstruct、Runner、ApplicationReadyEvent 谁先谁后

`@PostConstruct` 在 Bean 初始化阶段，发生在 `refresh` 过程中，此时内嵌服务器已经创建但还没启动；Runner 在 `refresh` 之后，服务器已经起来；`ApplicationReadyEvent` 在 Runner 之后。所以要在启动后调用本机接口，得用 Runner 或监听 `ApplicationReadyEvent`。

## 三、自动配置

### 自动配置原理

`@SpringBootApplication` 里的 `@EnableAutoConfiguration` 通过 `@Import(AutoConfigurationImportSelector.class)` 引入选择器。它去读候选清单（来自第三方 jar），经过去重、排除、条件过滤，把通过的配置类注册进容器。整个过程发生在 `refresh` 的 `ConfigurationClassPostProcessor` 那一步。

### @SpringBootApplication 由哪些注解组成

三个：`@SpringBootConfiguration`（本质就是 `@Configuration`）、`@EnableAutoConfiguration`、`@ComponentScan`。能立刻说出这三个和各自职责，比说"它是启动注解"强很多。

### @EnableAutoConfiguration 具体做了什么

两部分：`@AutoConfigurationPackage` 把启动类所在包名记下来，供后续框架（JPA 扫实体、MyBatis 扫 Mapper）使用；`@Import` 引入 `AutoConfigurationImportSelector` 挑自动配置。真正干活的是后者。

### 自动配置类从哪加载

Spring Boot 2.7 以前，读各 jar 里 `META-INF/spring.factories` 中 `EnableAutoConfiguration` 这个 key；2.7 起改读 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`，一行一个类名；3.0 起不再支持旧的 `spring.factories` 方式（其他用途仍然保留）。来源是第三方 jar，不是你项目里写的。

### 条件注解有哪些，@ConditionalOnMissingBean 有什么用

按条件决定装不装：`@ConditionalOnClass` 看 classpath 有没有某个类，`@ConditionalOnBean` / `@ConditionalOnMissingBean` 看容器里有没有某个 Bean，`@ConditionalOnProperty` 看配置值，`@ConditionalOnWebApplication` 看是不是 Web 应用。

`@ConditionalOnMissingBean` 是"用户自定义优先"的关键：只有你没定义，自动配置才补上。

### 怎么排除某个自动配置

三种写法：`@SpringBootApplication(exclude = XxxAutoConfiguration.class)`、`excludeName` 用类名，或者配置文件里写 `spring.autoconfigure.exclude`。

### 怎么自定义一个 starter

写一个 `@AutoConfiguration` 类，每个 Bean 上用 `@ConditionalOnClass` 保证依赖缺失时静默失效，用 `@ConditionalOnMissingBean` 让使用者能覆盖你的默认实现；再把类名写进 `AutoConfiguration.imports`。starter 本身通常是一个只管引依赖的 POM 模块，自动配置放在配套的 autoconfigure 模块里。

### 怎么知道哪些自动配置生效了

启动时加 `--debug`，或配置文件里写 `debug=true`，会打印自动配置报告，列出 Positive matches 和 Negative matches，以及每个条件通过或失败的原因。运行时也可以看 `/actuator/conditions`。

### 为什么我定义的 Bean 能覆盖自动配置

因为自动配置类上的 `@ConditionalOnMissingBean`：容器里已经有你定义的 Bean，它就不装了。这就是"默认配置可被覆盖"的机制，也是自动配置设计的核心约定。

## 四、配置

### 配置文件的加载位置和优先级

记一条主线：Jar 包外的 `config/` 目录 > Jar 包外的根目录 > Jar 包内的 `config/` 目录 > Jar 包内的根目录。也就是"包外覆盖包内，`config` 目录覆盖根目录"。部署时想覆盖配置，在 jar 同级放一个 `config/application.yml` 就行。

再加上一句更高的规则：命令行参数优先级最高，其次是环境变量和系统属性。面试一般不需要背全 17 级，讲清这个层次就够了。

### application.properties 和 application.yml 同时存在，谁生效

同一目录下两个都放，`.properties` 优先级更高，会覆盖 `.yml` 里的同名项。建议一个项目只用一种，避免混乱。

### profile 怎么用

`application-{profile}.yml` 在被激活时叠加在 `application.yml` 之上，同名配置以 profile 文件为准。激活方式有几种：配置文件里写 `spring.profiles.active`，命令行 `--spring.profiles.active=dev`，或环境变量 `SPRING_PROFILES_ACTIVE`。`application-default.*` 只在没激活任何 profile 时才生效。

### @ConfigurationProperties 和 @Value 的区别

`@Value("${server.port}")` 一次取一个值，支持 SpEL，适合零散配置。`@ConfigurationProperties` 按前缀把一整组配置绑定到一个类型安全的对象上，支持松散绑定、校验和元数据提示。只要有三个以上相关配置项，就该用 `@ConfigurationProperties`。

### 什么是松散绑定

配置名写法不同也能绑到同一个字段：`app.mailHost`、`app.mail-host`、`app.mail_host`，以及环境变量 `APP_MAILHOST`，都对应到 `mailHost`。这也是环境变量（没法用中划线）能干净地映射到配置项的原因。

## 五、内嵌容器

### 支持哪些内嵌容器，默认是哪个，怎么切换

默认 Tomcat，还可以用 Jetty、Undertow。切换方式是把 `spring-boot-starter-tomcat` 排除，再加 `spring-boot-starter-jetty` 或 `spring-boot-starter-undertow`。需要注意 Undertow 在 Spring Boot 4.0 已经不再作为内嵌容器支持。

### 内嵌 Tomcat 是什么时候创建、什么时候启动的

创建在 `refresh` 的 `onRefresh` 阶段，那时 Bean 还没实例化完；启动在 `refresh` 收尾阶段，由一个 Lifecycle 组件触发。所以 `@PostConstruct` 里拿得到 `ServletContext`，但访问本机端口会失败。完整过程见 [Boot扩展refresh.md](Boot扩展refresh.md)。

### 怎么改端口，server.port=0 有什么用

`server.port=8081` 改端口。设成 0 表示让容器自己挑一个空闲端口，测试里常用，避免并行跑时端口冲突，取端口用 `@LocalServerPort`。

### 怎么打成 war 部署到外部容器

三步：打包类型设为 `war`；主类继承 `SpringBootServletInitializer` 并覆盖 `configure`；把内嵌服务器依赖设为 `provided`，别打进包里。不过现在主流还是打可执行 jar，war 部署多是历史包袱或平台要求。

## 六、Boot 生态与其它高频

### Spring Boot 默认日志框架是什么

门面用 SLF4J，实现用 Logback。想换实现（比如换 Log4j2），排除 `spring-boot-starter-logging` 再引对应的 starter。

### Actuator 是什么，默认暴露哪些端点

加上 `spring-boot-starter-actuator` 后，它提供健康检查、指标、环境、映射、线程转储等端点，给监控和运维用。默认只通过 HTTP 暴露 `/health`（`/info` 在部分版本也暴露且默认为空），其余端点都是"已启用但未暴露"。

### enabled 和 exposed 有什么区别

enabled 指端点存在、Bean 被创建；exposed 指它能通过 HTTP 或 JMX 被访问。默认绝大多数端点 enabled 但没 exposed。控制方式：`management.endpoint.<id>.enabled` 管启用，`management.endpoints.web.exposure.include/exclude` 管暴露。把这两个搞混是 Actuator 最常见的错误。

### 怎么自定义健康检查

实现 `HealthIndicator`，返回 `Health.up()` 或 `Health.down()` 并带上详情。Bean 名去掉 `HealthIndicator` 后缀，就是聚合健康结果里的那个 key。

### Micrometer 是什么

指标领域的门面，可以理解成"指标界的 SLF4J"。Actuator 的 `/metrics`、`/prometheus` 都基于它。代码里用 Counter、Timer、Gauge 打点，Micrometer 负责导出到 Prometheus、Datadog 等后端。

### 生产环境怎么保护 Actuator

只暴露必要端点；把管理端口单独开（`management.server.port`），和业务端口隔离；敏感端点（`/env`、`/configprops`、`/heapdump`、`/threaddump`、`/shutdown`）用 Spring Security 保护。Boot 3 里用 `SecurityFilterChain` 配合 `EndpointRequest` 来限制。

### @SpringBootTest 和测试切片有什么区别

`@SpringBootTest` 加载完整上下文，最真实但最慢。切片只加载一层：`@WebMvcTest` 只管控制器（配 MockMvc），`@DataJpaTest` 只管仓库（默认内存库、事务回滚），`@JsonTest` 只管序列化。测一层用切片，端到端才用 `@SpringBootTest`。

### webEnvironment 有哪几种取值

`MOCK`（默认，不开真实服务器，配 MockMvc）、`RANDOM_PORT`（开，随机端口）、`DEFINED_PORT`（开，用配置的端口）、`NONE`（没有 Web 环境）。开了真实服务器的只有中间两个。

### Spring Boot 3 有哪些变化

基线升到 Java 17 和 Spring Framework 6；`javax.*` 全部换成 `jakarta.*`；支持 GraalVM 原生镜像和 AOT 处理；Hibernate 升到 6；`WebSecurityConfigurerAdapter` 被移除，改用 `SecurityFilterChain` Bean；测试里 `@MockBean` 从 3.4 起被 `@MockitoBean` 取代。补充一条常被问的：从 Spring Boot 2.6 起默认禁止循环依赖，要放开得设 `spring.main.allow-circular-references=true`。

### 怎么优雅停机

配置 `server.shutdown=graceful` 开启，配合 `spring.lifecycle.timeout-per-shutdown-phase` 设置等待时间。开启后停机时会先停止接收新请求，等处理中的请求跑完再关闭。
