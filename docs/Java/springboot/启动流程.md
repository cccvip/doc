我相信很多人都用过 Spring Boot，也都能说出 `SpringApplication.run` 是启动入口。但真被问到"启动分几步、Web 服务器什么时候创建、`@PostConstruct` 和 Runner 谁先执行"，往往只能含糊带过。

如果你看完很多篇启动流程还是记不住顺序，希望这篇能帮你把它串成一条线。本文会按 `SpringApplication.run` 的实际执行顺序，从构造 `SpringApplication` 一直讲到应用 ready，并用 `[run]` / `[refresh]` 标记当前所在的层级。如果只为面试，可以直接滑到最后的**小结**。

> 基于 Spring Boot 2.5.x。代码片段是简化示意，省略了 Banner、耗时统计等；不同版本方法签名略有差异，主流程一致。

# 总览

**一句话：`SpringApplication.run` 先准备 Environment，再创建并 refresh ApplicationContext，最后回调 Runner。**

整条时间线：

| 序号 | 阶段 | 所在层 | 关键动作 |
|---|---|---|---|
| 0 | 构造 `SpringApplication` | 构造 | 推断 Web 类型、加载 Initializer / Listener |
| 1 | `prepareEnvironment` | `[run]` | 读配置、激活 profile |
| 2 | `createApplicationContext` | `[run]` | 创建 Servlet / Reactive / 普通容器 |
| 3 | `prepareContext` | `[run]` | 设置 Environment、应用 Initializer、注册主配置类 |
| 4 | `refreshContext` | `[run]` → `[refresh]` | 自动装配、实例化 Bean、创建并启动 Web 服务器 |
| 5 | `afterRefresh` + `callRunners` | `[run]` | 执行 Runner |
| 6 | `started` / `running` | `[run]` | 发布启动完成事件 |

```text
[构造] new SpringApplication
  → [run] 1 prepareEnvironment
  → [run] 2 createApplicationContext
  → [run] 3 prepareContext
  → [run] 4 refreshContext
        └─ [refresh] prepareRefresh → ... → onRefresh → ... → finishRefresh
  → [run] 5 afterRefresh + callRunners
  → [run] 6 listeners.started / running
```

先记住这条线，下面逐段展开。

# 第 0 阶段：构造 SpringApplication

**输入**：`primarySource`（通常是 `ApiApplication.class`）。

**动作**：`new SpringApplication(...)` 时做三件事：

```java
public SpringApplication(ResourceLoader resourceLoader, Class<?>... primarySources) {
    this.resourceLoader = resourceLoader;
    this.primarySources = new LinkedHashSet<>(Arrays.asList(primarySources));

    // ① 根据 classpath 推断 Web 类型
    this.webApplicationType = WebApplicationType.deduceFromClasspath();

    // ② 从 spring.factories 加载 Initializer 和 Listener
    setInitializers((Collection) getSpringFactoriesInstances(ApplicationContextInitializer.class));
    setListeners((Collection) getSpringFactoriesInstances(ApplicationListener.class));

    // ③ 推断 main 方法所在类
    this.mainApplicationClass = deduceMainApplicationClass();
}
```

**输出**：

- `webApplicationType`：`SERVLET` / `REACTIVE` / `NONE`；
- `initializers`：在 refresh 之前对 Context 做编程式初始化；
- `listeners`：监听启动事件；
- `mainApplicationClass`：主类。

**下一步依赖它什么**：第 2 阶段创建 Context 时，要用 `webApplicationType` 决定创建哪种容器。

# 第 1 阶段：准备 Environment

**输入**：命令行参数 `args`。

**动作**：创建并配置 `Environment`。

```java
private ConfigurableEnvironment prepareEnvironment(SpringApplicationRunListeners listeners,
        ApplicationArguments applicationArguments) {

    // ① 创建 Environment（Servlet 应用是 StandardServletEnvironment）
    ConfigurableEnvironment environment = getOrCreateEnvironment();

    // ② 配置：命令行参数、profile 等
    configureEnvironment(environment, applicationArguments.getSourceArgs());
    ConfigurationPropertySources.attach(environment);

    // ③ 发布 environmentPrepared 事件：application.yml 在这一步加载
    listeners.environmentPrepared(environment);

    // ④ 把 spring.main.* 绑定到 SpringApplication
    bindToSpringApplication(environment);

    return environment;
}
```

**输出**：一个已经加载了 `application.yml`、profile、命令行参数的 `Environment`。

**为什么必须最先做**：后面创建 Context、决定 Web 类型、加载自动配置，都要读配置。没有 Environment，后面的步骤没有依据。

# 第 2 阶段：创建 ApplicationContext

**输入**：`webApplicationType`。

**动作**：按类型创建容器。

```java
protected ConfigurableApplicationContext createApplicationContext() {
    return this.applicationContextFactory.create(this.webApplicationType);
}

// ApplicationContextFactory.DEFAULT（简化）
switch (webApplicationType) {
    case SERVLET:
        return new AnnotationConfigServletWebServerApplicationContext();
    case REACTIVE:
        return new AnnotationConfigReactiveWebServerApplicationContext();
    default:
        return new AnnotationConfigApplicationContext();
}
```

| Web 类型 | ApplicationContext |
|---|---|
| `SERVLET` | `AnnotationConfigServletWebServerApplicationContext` |
| `REACTIVE` | `AnnotationConfigReactiveWebServerApplicationContext` |
| `NONE` | `AnnotationConfigApplicationContext` |

**输出**：一个**空的** ApplicationContext，里面还没有 BeanDefinition，也没有 Bean 实例。

**下一步依赖它什么**：第 3 阶段要往这个 Context 里注册主配置类。

# 第 3 阶段：prepareContext

**输入**：刚创建的空 Context + 第 1 阶段的 Environment。

**动作**：把 Environment、Initializer、主配置类交给 Context。

```java
private void prepareContext(ConfigurableApplicationContext context,
        ConfigurableEnvironment environment, SpringApplicationRunListeners listeners,
        ApplicationArguments applicationArguments) {

    // ① 设置 Environment
    context.setEnvironment(environment);

    // ② 应用 Initializer：在 refresh 之前对 Context 做定制
    applyInitializers(context);

    // ③ 发布 contextPrepared 事件
    listeners.contextPrepared(context);

    // ④ 注册特殊 Bean：启动参数等
    context.getBeanFactory().registerSingleton("springApplicationArguments", applicationArguments);

    // ⑤ 把主配置类（ApiApplication）注册进容器
    load(context, getAllSources().toArray(new Object[0]));

    // ⑥ 发布 contextLoaded 事件
    listeners.contextLoaded(context);
}
```

**输出**：Context 里已经有了主配置类的 BeanDefinition，但**还没有执行 refresh**，所以 `@ComponentScan`、`@EnableAutoConfiguration` 都还没解析。

**下一步依赖它什么**：第 4 阶段 `refresh()` 会解析这些 BeanDefinition，触发自动装配和 Bean 创建。

# 第 4 阶段：refreshContext

**输入**：已经注册了主配置类的 Context。

**动作**：调用 `AbstractApplicationContext.refresh()`。注意：从这里开始，时间线从 `[run]` 进入 `[refresh]`。

## 先给 refresh 的地图

```java
public void refresh() throws BeansException, IllegalStateException {
    prepareRefresh();

    // ① 创建 BeanFactory
    ConfigurableListableBeanFactory beanFactory = obtainFreshBeanFactory();
    prepareBeanFactory(beanFactory);

    try {
        postProcessBeanFactory(beanFactory);

        // ② 执行 BeanFactoryPostProcessor：自动装配在这里
        invokeBeanFactoryPostProcessors(beanFactory);

        // ③ 注册 BeanPostProcessor
        registerBeanPostProcessors(beanFactory);

        initMessageSource();
        initApplicationEventMulticaster();

        // ④ 创建内嵌 Web 服务器（还没启动）
        onRefresh();

        registerListeners();

        // ⑤ 实例化所有非懒加载单例
        finishBeanFactoryInitialization(beanFactory);

        // ⑥ 启动 Web 服务器、发布 ContextRefreshedEvent
        finishRefresh();
    }
    catch (BeansException ex) {
        destroyBeans();
        cancelRefresh(ex);
        throw ex;
    }
}
```

和启动流程关系最大的五步：

| 步骤 | 做什么 | 对启动的影响 |
|---|---|---|
| `invokeBeanFactoryPostProcessors` | 执行 `ConfigurationClassPostProcessor` | 自动装配在这里发生 |
| `registerBeanPostProcessors` | 注册 `@Autowired`、AOP 等后置处理器 | 后面实例化 Bean 时才能用 |
| `onRefresh` | `createWebServer()` | Web 服务器**创建**，但端口还没绑定 |
| `finishBeanFactoryInitialization` | 实例化所有非懒加载单例 | `@PostConstruct` 在这里执行 |
| `finishRefresh` | `startWebServer()` | Web 服务器**启动**，开始接收请求 |

## Web 服务器：创建和启动是两回事

**创建**在 `onRefresh()`：

```java
@Override
protected void onRefresh() {
    super.onRefresh();
    createWebServer();   // 创建 Tomcat / Jetty / Undertow 对象
}
```

**启动**在 `finishRefresh()`：

```java
@Override
protected void finishRefresh() {
    super.finishRefresh();
    WebServer webServer = startWebServer();   // 绑定端口，开始接收请求
    if (webServer != null) {
        publishEvent(new ServletWebServerInitializedEvent(webServer, this));
    }
}
```

所以：

- `onRefresh` 时服务器对象有了，但**端口还没绑定**；
- `finishBeanFactoryInitialization` 里的 `@PostConstruct`，服务器还没启动；
- `finishRefresh` 之后，服务器才真正可用。

**输出**：一个完成 refresh 的 Context，所有非懒加载单例已创建，Web 服务器已启动。

# 第 5 阶段：afterRefresh + Runner

**输入**：已经 refresh 完成的 Context。

**动作**：执行 `ApplicationRunner` 和 `CommandLineRunner`。

```java
private void callRunners(ApplicationContext context, ApplicationArguments args) {
    List<Object> runners = new ArrayList<>();
    runners.addAll(context.getBeansOfType(ApplicationRunner.class).values());
    runners.addAll(context.getBeansOfType(CommandLineRunner.class).values());
    AnnotationAwareOrderComparator.sort(runners);

    for (Object runner : new LinkedHashSet<>(runners)) {
        if (runner instanceof ApplicationRunner) {
            callRunner((ApplicationRunner) runner, args);
        }
        if (runner instanceof CommandLineRunner) {
            callRunner((CommandLineRunner) runner, args);
        }
    }
}
```

**输出**：启动后初始化逻辑执行完毕。

**此时的状态**：容器里的 Bean 已就绪，Web 服务器已启动。适合做缓存预热、调用本机接口、初始化业务数据。

# 第 6 阶段：started / running

**动作**：通知 `SpringApplicationRunListener`。

```java
listeners.started(context);   // 容器已刷新、Runner 已执行
// ...
listeners.running(context);   // 应用已就绪
```

对应的事件：

- `ApplicationStartedEvent`：容器 refresh 完成、Runner 执行前；
- `ApplicationReadyEvent`：应用已就绪，可以对外服务。

如果启动过程中抛异常，会走 `handleRunFailure`：发布 `ApplicationFailedEvent`、关闭 context、把异常抛出去。

**输出**：应用进入 running 状态。

# 时间线总表

| 阶段 | 谁执行 | 关键动作 | Web 服务器状态 | Bean 状态 |
|---|---|---|---|---|
| 0 构造 | `new SpringApplication` | 推断 Web 类型、加载 Initializer / Listener | 无 | 无 |
| 1 Environment | `[run]` | 读 application.yml、激活 profile | 无 | 无 |
| 2 Context | `[run]` | 创建空容器 | 无 | 无 |
| 3 prepareContext | `[run]` | 设置 Environment、注册主配置类 | 无 | 只有 BeanDefinition，无实例 |
| 4 refresh | `[refresh]` | 自动装配、实例化、创建/启动服务器 | `onRefresh` 创建，`finishRefresh` 启动 | 单例在这里创建 |
| 5 Runner | `[run]` | `callRunners` | 已启动 | 全部单例就绪 |
| 6 started/running | `[run]` | 发布启动完成事件 | 已启动 | 就绪 |

# 实战与常见坑

## 场景：启动后初始化，选 Runner 还是 @PostConstruct

| 方式 | 执行时机 | 适合做什么 |
|---|---|---|
| `@PostConstruct` | `finishBeanFactoryInitialization`，Web 服务器还没启动 | 初始化当前 Bean 自己的资源 |
| `ApplicationListener<ContextRefreshedEvent>` | `finishRefresh` 发布事件时 | 依赖整个容器就绪的逻辑 |
| `ApplicationRunner` / `CommandLineRunner` | `refresh` 之后，Web 服务器已启动 | 调用本机接口、预热缓存、初始化业务数据 |

**需要在启动后调用本服务 HTTP 接口的，用 Runner，不要用 `@PostConstruct`。**

## 常见坑

1. **在 `@PostConstruct` 里访问本机端口**：Web 服务器还没 `start()`，会连接失败。
2. **`CommandLineRunner` 抛异常**：会触发 `handleRunFailure`，整个应用启动失败。
3. **Runner 里做耗时操作**：会拖慢启动，必要时改成异步，或放到 `ApplicationReadyEvent` 之后。
4. **多个 Runner 顺序不确定**：用 `@Order` / `Ordered` 显式排序。
5. **`spring.main.lazy-initialization=true`**：Bean 延迟初始化，Runner 里第一次 `getBean` 才触发创建，启动耗时统计会失真。
6. **`spring.main.allow-circular-references=false`（2.6+ 默认）**：循环依赖直接启动失败。
7. **`ApplicationContextInitializer` 里拿不到 Bean**：它执行时 BeanDefinition 还没加载完，只能操作 Environment / BeanFactory。

# 小结

我一向不太喜欢写总结，因为该说的正文里都说了。不过考虑到很多读者是冲着面试来的，还是列成清单：

1. **启动分几步？** 构造 → Environment → Context → prepareContext → refresh → Runner → started/running。
2. **Web 类型怎么推断？** 有 `DispatcherServlet` + `Servlet` → SERVLET；只有 WebFlux → REACTIVE；否则 NONE。
3. **自动装配在启动流程的哪一步？** `refresh()` → `invokeBeanFactoryPostProcessors` → `ConfigurationClassPostProcessor`。
4. **Web 服务器什么时候创建、什么时候启动？** `onRefresh()` 创建，`finishRefresh()` 启动。
5. **Runner 和 `@PostConstruct` 的区别？** `@PostConstruct` 在 Bean 初始化阶段，服务器还没启动；Runner 在 `refresh()` 之后，服务器已启动。
6. **启动失败怎么处理？** `handleRunFailure` 发布 `ApplicationFailedEvent`、关闭 context、抛出异常。
7. **`ApplicationContextInitializer` 能做什么？** 在 refresh 之前操作 Environment / BeanFactory，不能拿 Bean。
