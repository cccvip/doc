`SpringApplication.run(ApiApplication.class, args)` 这一行背后，Spring Boot 做了很多事：推断应用类型、准备 Environment、创建 ApplicationContext、执行自动装配、启动内嵌 Web 服务器、回调 Runner。很多人只知道"它会启动 Spring"，但面试一问"启动过程中各个扩展点按什么顺序执行、Web 服务器是什么时候起来的"，就说不清了。

这篇按 `run` 方法的执行顺序，把启动流程拆成几段走一遍。自动装配的细节在 [starter.md](starter.md)，这里重点讲"启动的骨架"。如果只为面试，可以直接滑到最后的**小结**。

> 基于 Spring Boot 2.5.x。不同版本方法签名略有差异，主流程一致。

# 总览

**一句话：`SpringApplication.run` 分三段——准备 Environment、创建并 refresh ApplicationContext、回调 Runner 和 Listener。**

```text
SpringApplication.run
  ├─ 1. 创建 SpringApplication：推断 Web 类型、加载 Initializer / Listener
  ├─ 2. prepareEnvironment：读配置、激活 profile、发布 environmentPrepared
  ├─ 3. createApplicationContext：Servlet / Reactive / 普通容器
  ├─ 4. prepareContext：setEnvironment、applyInitializers、注册主配置类
  ├─ 5. refreshContext：refresh() → 自动装配 → 实例化 Bean → 启动 Web 服务器
  ├─ 6. afterRefresh + callRunners：执行 ApplicationRunner / CommandLineRunner
  └─ 7. listeners.started / running
```

# 核心概念

## SpringApplication 的构造

`new SpringApplication(primarySource)` 时会做几件事：

- 推断 `webApplicationType`：`SERVLET` / `REACTIVE` / `NONE`；
- 从 `spring.factories` 加载 `ApplicationContextInitializer`；
- 从 `spring.factories` 加载 `ApplicationListener`；
- 推断主类 `mainApplicationClass`。

## 三种 ApplicationContext

| Web 类型 | ApplicationContext |
|---|---|
| `SERVLET` | `AnnotationConfigServletWebServerApplicationContext` |
| `REACTIVE` | `AnnotationConfigReactiveWebServerApplicationContext` |
| `NONE` | `AnnotationConfigApplicationContext` |

## SpringApplicationRunListener

`run` 的每个阶段都会通知监听器：

`starting` → `environmentPrepared` → `contextPrepared` → `contextLoaded` → `started` → `running`；失败时 `failed`。

## Runner

容器 refresh 完成后执行，用来做"启动后初始化"：

- `ApplicationRunner`：参数是 `ApplicationArguments`；
- `CommandLineRunner`：参数是原始 `String... args`。

两者都按 `@Order` / `Ordered` 排序。

# 源码分析

## 构造：推断 Web 类型、加载扩展点

```java
public SpringApplication(ResourceLoader resourceLoader, Class<?>... primarySources) {
    this.resourceLoader = resourceLoader;
    this.primarySources = new LinkedHashSet<>(Arrays.asList(primarySources));

    // ① 根据 classpath 推断 Web 类型
    this.webApplicationType = WebApplicationType.deduceFromClasspath();

    // ② 从 spring.factories 加载初始化器和监听器
    this.bootstrapRegistryInitializers = new ArrayList<>(
            getSpringFactoriesInstances(BootstrapRegistryInitializer.class));
    setInitializers((Collection) getSpringFactoriesInstances(ApplicationContextInitializer.class));
    setListeners((Collection) getSpringFactoriesInstances(ApplicationListener.class));

    // ③ 推断 main 方法所在类
    this.mainApplicationClass = deduceMainApplicationClass();
}
```

`WebApplicationType.deduceFromClasspath()` 的判断逻辑：

- 有 `DispatcherServlet` 且有 `Servlet` → `SERVLET`；
- 只有 `DispatcherHandler`（WebFlux）→ `REACTIVE`；
- 否则 → `NONE`。

## run 主流程

简化后的 `run`：

```java
public ConfigurableApplicationContext run(String... args) {
    StopWatch stopWatch = new StopWatch();
    stopWatch.start();

    DefaultBootstrapContext bootstrapContext = createBootstrapContext();
    ConfigurableApplicationContext context = null;

    configureHeadlessProperty();
    SpringApplicationRunListeners listeners = getRunListeners(args);
    listeners.starting(bootstrapContext, this.mainApplicationClass);

    try {
        ApplicationArguments applicationArguments = new DefaultApplicationArguments(args);

        // ① 准备 Environment
        ConfigurableEnvironment environment =
                prepareEnvironment(listeners, bootstrapContext, applicationArguments);
        configureIgnoreBeanInfo(environment);
        Banner printedBanner = printBanner(environment);

        // ② 创建 ApplicationContext
        context = createApplicationContext();
        context.setApplicationStartup(this.applicationStartup);

        // ③ 准备上下文
        prepareContext(bootstrapContext, context, environment, listeners,
                applicationArguments, printedBanner);

        // ④ 刷新容器：自动装配、实例化 Bean、启动 Web 服务器
        refreshContext(context);

        // ⑤ 启动后扩展
        afterRefresh(context, applicationArguments);
        stopWatch.stop();
        listeners.started(context);

        // ⑥ 执行 Runner
        callRunners(context, applicationArguments);
    }
    catch (Throwable ex) {
        handleRunFailure(context, ex, listeners);
        throw new IllegalStateException(ex);
    }

    try {
        listeners.running(context);
    }
    catch (Throwable ex) {
        handleRunFailure(context, ex, null);
        throw new IllegalStateException(ex);
    }
    return context;
}
```

## prepareEnvironment：先有配置，才有容器

```java
private ConfigurableEnvironment prepareEnvironment(SpringApplicationRunListeners listeners,
        DefaultBootstrapContext bootstrapContext, ApplicationArguments applicationArguments) {

    // ① 创建或获取 Environment（StandardServletEnvironment 等）
    ConfigurableEnvironment environment = getOrCreateEnvironment();

    // ② 配置：命令行参数、profile 等
    configureEnvironment(environment, applicationArguments.getSourceArgs());
    ConfigurationPropertySources.attach(environment);

    // ③ 发布 environmentPrepared 事件：application.yml 在这一步加载
    listeners.environmentPrepared(bootstrapContext, environment);

    // ④ 把 spring.main.* 绑定到 SpringApplication
    bindToSpringApplication(environment);

    return environment;
}
```

关键点：**Environment 必须在创建容器之前准备好**，因为后面创建 `ApplicationContext`、决定 Web 类型、加载自动配置，都要读配置。

## createApplicationContext：按 Web 类型创建容器

```java
protected ConfigurableApplicationContext createApplicationContext() {
    return this.applicationContextFactory.create(this.webApplicationType);
}

// ApplicationContextFactory.DEFAULT
ApplicationContextFactory DEFAULT = (webApplicationType) -> {
    switch (webApplicationType) {
        case SERVLET:
            return new AnnotationConfigServletWebServerApplicationContext();
        case REACTIVE:
            return new AnnotationConfigReactiveWebServerApplicationContext();
        default:
            return new AnnotationConfigApplicationContext();
    }
};
```

## prepareContext：把主配置类交给容器

```java
private void prepareContext(DefaultBootstrapContext bootstrapContext, ConfigurableApplicationContext context,
        ConfigurableEnvironment environment, SpringApplicationRunListeners listeners,
        ApplicationArguments applicationArguments, Banner printedBanner) {

    // ① 设置 Environment
    context.setEnvironment(environment);

    // ② 应用初始化器
    postProcessApplicationContext(context);
    applyInitializers(context);

    // ③ 发布 contextPrepared / contextLoaded
    listeners.contextPrepared(context);
    bootstrapContext.close(context);

    // ④ 注册特殊 Bean：启动参数、Banner
    ConfigurableListableBeanFactory beanFactory = context.getBeanFactory();
    beanFactory.registerSingleton("springApplicationArguments", applicationArguments);
    if (printedBanner != null) {
        beanFactory.registerSingleton("springBootBanner", printedBanner);
    }

    // ⑤ 把主配置类注册进容器
    Set<Object> sources = getAllSources();
    load(context, sources.toArray(new Object[0]));

    listeners.contextLoaded(context);
}
```

`load` 会把 `ApiApplication` 注册成 BeanDefinition；`@SpringBootApplication` 上的 `@ComponentScan`、`@EnableAutoConfiguration` 要等到 `refresh()` 阶段才解析。

## refreshContext：refresh 的骨架

`refreshContext` 最终调用 `AbstractApplicationContext.refresh()`：

```java
public void refresh() throws BeansException, IllegalStateException {
    synchronized (this.startupShutdownMonitor) {
        prepareRefresh();

        // ① 创建 BeanFactory
        ConfigurableListableBeanFactory beanFactory = obtainFreshBeanFactory();
        prepareBeanFactory(beanFactory);

        try {
            postProcessBeanFactory(beanFactory);

            // ② 执行 BeanFactoryPostProcessor：自动装配在这一步
            invokeBeanFactoryPostProcessors(beanFactory);

            // ③ 注册 BeanPostProcessor
            registerBeanPostProcessors(beanFactory);

            // ④ 初始化事件、消息源
            initMessageSource();
            initApplicationEventMulticaster();

            // ⑤ 创建内嵌 Web 服务器（还没 start）
            onRefresh();

            registerListeners();

            // ⑥ 实例化所有非懒加载单例
            finishBeanFactoryInitialization(beanFactory);

            // ⑦ 启动 Web 服务器、发布 ContextRefreshedEvent
            finishRefresh();
        }
        catch (BeansException ex) {
            destroyBeans();
            cancelRefresh(ex);
            throw ex;
        }
        finally {
            resetCommonCaches();
        }
    }
}
```

自动装配的 `ConfigurationClassPostProcessor` 就在第 ② 步 `invokeBeanFactoryPostProcessors` 里执行，细节见 [starter.md](starter.md)。

## Web 服务器什么时候创建、什么时候启动

这是面试常问的点，分两步：

**创建**发生在 `onRefresh()`：

```java
@Override
protected void onRefresh() {
    super.onRefresh();
    try {
        createWebServer();          // 创建 Tomcat / Jetty / Undertow
    }
    catch (Throwable ex) {
        throw new ApplicationContextException("Unable to start web server", ex);
    }
}
```

**启动**发生在 `finishRefresh()`：

```java
@Override
protected void finishRefresh() {
    super.finishRefresh();
    WebServer webServer = startWebServer();   // 真正绑定端口、开始接收请求
    if (webServer != null) {
        publishEvent(new ServletWebServerInitializedEvent(webServer, this));
    }
}
```

所以：

- `onRefresh` 时 Web 服务器对象已经有了，但**端口还没绑定**；
- `finishBeanFactoryInitialization` 期间执行的 `@PostConstruct`，Web 服务器还没 start；
- `ApplicationRunner` / `CommandLineRunner` 在 `refresh()` 之后执行，此时服务器已经启动。

## afterRefresh 与 callRunners

```java
protected void afterRefresh(ConfigurableApplicationContext context, ApplicationArguments args) {
    // 默认空实现，留给子类扩展
}

private void callRunners(ApplicationContext context, ApplicationArguments args) {
    List<Object> runners = new ArrayList<>();
    runners.addAll(context.getBeansOfType(ApplicationRunner.class).values());
    runners.addAll(context.getBeansOfType(CommandLineRunner.class).values());
    AnnotationAwareOrderComparator.sort(runners);

    for (Object runner : new LinkedHashSet<>(runners)) {
        if (runner instanceof ApplicationRunner) {
            callRunner((ApplicationRunner) runner, args);
        }
        if (runner instanceof CommandLineRunner) {
            callRunner((CommandLineRunner) runner, args);
        }
    }
}
```

## 异常处理

`run` 里的 `catch` 会调用 `handleRunFailure`：

- 发布 `ApplicationFailedEvent`；
- 关闭已创建的 context；
- 把异常继续抛出。

所以 `CommandLineRunner` 里抛异常会导致启动失败，而不是"启动成功但日志报错"。

# 实战与常见坑

## 场景：启动后初始化，选 Runner 还是 @PostConstruct

| 方式 | 执行时机 | 适合做什么 |
|---|---|---|
| `@PostConstruct` | Bean 初始化阶段，Web 服务器还没 start | 初始化当前 Bean 自己的资源 |
| `ApplicationListener<ContextRefreshedEvent>` | `refresh()` 完成后 | 依赖整个容器就绪的逻辑 |
| `ApplicationRunner` / `CommandLineRunner` | `refresh()` 之后，Web 服务器已启动 | 调用本机接口、预热缓存、初始化业务数据 |

**需要在启动后调用本服务 HTTP 接口的，用 Runner，不要用 `@PostConstruct`。**

## 常见坑

1. **在 `@PostConstruct` 里访问本机端口**：Web 服务器还没 `start()`，会连接失败。
2. **`CommandLineRunner` 抛异常**：会触发 `handleRunFailure`，整个应用启动失败。
3. **Runner 里做耗时操作**：会拖慢启动，必要时改成异步或放到 `ApplicationReadyEvent` 之后。
4. **多个 Runner 顺序不确定**：用 `@Order` / `Ordered` 显式排序。
5. **`spring.main.lazy-initialization=true`**：Bean 延迟初始化，Runner 里第一次 `getBean` 才触发创建，启动耗时统计会失真。
6. **`spring.main.allow-circular-references=false`（2.6+ 默认）**：循环依赖直接启动失败，别再假设三级缓存能兜底。
7. **`ApplicationContextInitializer` 里拿不到 Bean**：它执行时 BeanDefinition 还没加载完，只能操作 Environment / BeanFactory。

# 小结

我一向不太喜欢写总结，因为该说的正文里都说了。不过考虑到很多读者是冲着面试来的，还是列成清单：

1. **`SpringApplication.run` 分几段？** 准备 Environment → 创建 Context → prepareContext → refresh → afterRefresh → Runner → started/running。
2. **Web 类型怎么推断？** 有 `DispatcherServlet` + `Servlet` → SERVLET；只有 WebFlux → REACTIVE；否则 NONE。
3. **自动装配在启动流程的哪一步？** `refresh()` → `invokeBeanFactoryPostProcessors` → `ConfigurationClassPostProcessor`。
4. **Web 服务器什么时候创建、什么时候启动？** `onRefresh()` 创建，`finishRefresh()` 启动。
5. **Runner 和 `@PostConstruct` 的区别？** `@PostConstruct` 在 Bean 初始化阶段，Web 服务器还没启动；Runner 在 `refresh()` 之后，服务器已启动。
6. **启动失败怎么处理？** `handleRunFailure` 发布 `ApplicationFailedEvent`、关闭 context、抛出异常。
7. **`ApplicationContextInitializer` 能做什么？** 在 refresh 之前操作 Environment / BeanFactory，不能拿 Bean。
