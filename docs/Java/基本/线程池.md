# what

线程池是 Java 提供的线程复用机制：预先维护一批线程，任务提交到队列，由线程循环取出执行，避免频繁创建/销毁线程。

一句话核心：**ThreadPoolExecutor 就是一个「核心线程 + 任务队列 + 最大线程 + 拒绝策略」的组合。**

# 七个核心参数

```java
public ThreadPoolExecutor(int corePoolSize,
                          int maximumPoolSize,
                          long keepAliveTime,
                          TimeUnit unit,
                          BlockingQueue<Runnable> workQueue,
                          ThreadFactory threadFactory,
                          RejectedExecutionHandler handler)
```

| 参数 | 含义 |
|---|---|
| `corePoolSize` | 核心线程数，默认常驻 |
| `maximumPoolSize` | 最大线程数 |
| `keepAliveTime` + `unit` | 超出核心数的空闲线程存活时间 |
| `workQueue` | 任务队列 |
| `threadFactory` | 线程工厂，建议自定义线程名 |
| `handler` | 拒绝策略 |

# 任务提交流程（背这一段）

1. 当前线程数 < `corePoolSize`：新建核心线程执行；
2. 否则尝试放入 `workQueue`；
3. 队列满了，且线程数 < `maximumPoolSize`：新建非核心线程执行；
4. 队列满且线程数达到 `maximumPoolSize`：执行拒绝策略。

注意顺序：**先入队，队列满了才扩容到 max**。所以如果用了无界队列，`maximumPoolSize` 永远不会生效。

# 八股速查

## 1. 为什么线程池要用 ThreadPoolExecutor 而不是 Executors？

`Executors` 的快捷工厂有坑：

- `newFixedThreadPool` / `newSingleThreadExecutor`：使用**无界** `LinkedBlockingQueue`，任务堆积可能 OOM，且 `maximumPoolSize` 无效；
- `newCachedThreadPool`：`maximumPoolSize = Integer.MAX_VALUE` + `SynchronousQueue`，可能创建海量线程；
- `newScheduledThreadPool`：队列无界。

所以《阿里巴巴 Java 开发手册》要求直接用 `ThreadPoolExecutor` 显式指定参数。

## 2. 常见队列怎么选？

| 队列 | 特点 |
|---|---|
| `ArrayBlockingQueue` | 有界数组，推荐 |
| `LinkedBlockingQueue` | 默认无界（`Integer.MAX_VALUE`），慎用 |
| `SynchronousQueue` | 不存储，直接交给线程，配合大 max 使用 |
| `PriorityBlockingQueue` | 优先级，无界 |
| `DelayQueue` | 延迟任务 |

## 3. 四种拒绝策略

- `AbortPolicy`（默认）：抛 `RejectedExecutionException`；
- `CallerRunsPolicy`：交给提交任务的线程执行，起到反压作用；
- `DiscardPolicy`：静默丢弃；
- `DiscardOldestPolicy`：丢掉最老的任务再提交。

生产上一般选 `AbortPolicy` 或 `CallerRunsPolicy`，不要静默丢任务。

## 4. 线程池大小怎么设？

- CPU 密集：`N + 1`；
- IO 密集：`2N` 或 `N × (1 + 等待时间 / 计算时间)`；
- 最终以压测为准，别照抄公式。

## 5. 线程复用原理？

`Worker` 继承 AQS，本质是一个 Runnable。线程启动后循环调用 `getTask()` 从队列取任务，取到就执行，取不到就阻塞或退出，所以线程不会被销毁。

## 6. 线程池有哪些状态？

`RUNNING → SHUTDOWN → TIDYING → TERMINATED`，以及跳过 SHUTDOWN 的 `STOP`。状态和线程数打包在 `ctl` 里。

## 7. shutdown 和 shutdownNow 的区别？

- `shutdown()`：不再接新任务，已提交的（含队列里的）会执行完；
- `shutdownNow()`：不再接新任务，中断正在执行的线程，并返回队列里没执行的任务。

## 8. submit 和 execute 的区别？

- `execute(Runnable)`：异常会抛给 `UncaughtExceptionHandler`；
- `submit(...)`：返回 `Future`，异常被包进 `Future`，不调用 `get()` 就看不到，容易被吞掉。

## 9. 核心线程会回收吗？

默认不会。设置 `allowCoreThreadTimeOut(true)` 后，核心线程空闲超过 `keepAliveTime` 也会退出。

## 10. 线程池能动态调整吗？

可以：`setCorePoolSize`、`setMaximumPoolSize`、`setRejectedExecutionHandler`。注意 `core <= max`，且缩容不会立刻终止正在执行的任务。

# 实战场景

## 场景一：Web 请求处理

不要每个请求 new 线程，用固定大小线程池 + 有界队列 + `CallerRunsPolicy`，让过载时反压到 Tomcat 线程。

## 场景二：批量任务

分片提交，控制单批大小；用 `CompletableFuture` 组合结果，注意自定义线程池，别用默认的 `ForkJoinPool.commonPool()`。

## 场景三：异步解耦

下单后发消息、写日志等非核心链路异步化，用独立线程池隔离，避免拖垮主流程。

## 场景四：定时任务

`ScheduledThreadPoolExecutor`，注意任务里抛异常会导致后续执行停止（`scheduleAtFixedRate`）。

# 常见坑

1. **无界队列**：任务堆积到 OOM，`max` 形同虚设；
2. **父子任务用同一个池**：父任务等子任务，线程全被父任务占满 → 死锁；
3. **ThreadLocal 不清理**：线程复用导致上下文串号；
4. **异常被吞**：用 `submit` 却不 `get()`，任务失败无感知；
5. **线程不命名**：排查问题时线程栈全是 `pool-1-thread-x`；
6. **关闭不等待**：`shutdown()` 后没 `awaitTermination`，任务可能被中断。

# 参数速查

```java
new ThreadPoolExecutor(
    8,                                  // core
    16,                                 // max
    60, TimeUnit.SECONDS,               // keepAlive
    new ArrayBlockingQueue<>(1000),     // 有界队列
    new ThreadFactory() {               // 命名线程
        private final AtomicInteger i = new AtomicInteger(1);
        public Thread newThread(Runnable r) {
            return new Thread(r, "biz-pool-" + i.getAndIncrement());
        }
    },
    new ThreadPoolExecutor.CallerRunsPolicy()
);
```
