反射是"框架魔法"的地基——Spring 的依赖注入、AOP、MVC 全都建立在它之上。这篇先把它能干什么讲清楚，再落到 Spring 里看看它到底用反射做了什么、代价又是什么。

> 反射和注解是一对搭档：注解负责"声明"，反射负责"读取并执行"。注解本身见 [注解.md](注解.md)。

# 总览

Java 反射（Reflection）允许程序在**运行时**动态获取类的信息（字段、方法、构造器、注解、泛型）并操作它们：不 `new` 就能创建实例，编译期不知道方法名也能调用，`private` 也能读写。

入口只有一个——`java.lang.Class` 对象。拿到它，就等于拿到了这个类的"说明书"。反射能做的事归纳成四类：

1. **创建对象**：`clazz.getDeclaredConstructor().newInstance()`；
2. **调用方法**：`method.invoke(obj, args...)`；
3. **读写字段**：`field.set(obj, val)` / `field.get(obj)`；
4. **读元信息**：注解、泛型、修饰符等。

它的价值在于**动态性**：框架在编译期根本不知道用户写了哪些类，只能靠反射在运行时统一处理。

# 核心 API 与示例

下面所有示例用同一个实体类，避免前后不一致：

```java
package com.test;

public class MyClass {
    private String name = "hello";   // 私有字段
    private static int count;        // 静态字段

    public MyClass() {}
    public MyClass(String name) { this.name = name; }

    public String greet(String who) { return name + ", " + who; }
    private void secret() { System.out.println("private method called"); }
}
```

## 1. 获取 Class 对象（三种方式）

```java
Class<?> c1 = MyClass.class;                       // 类字面量，最常用、最安全
Class<?> c2 = new MyClass().getClass();            // 通过对象
Class<?> c3 = Class.forName("com.test.MyClass");   // 全限定类名，最灵活
```

区别：`Class.forName` 会**触发静态初始化**（执行 static 块），`ClassLoader.loadClass` 不会。

## 2. 创建对象

```java
// newInstance() 从 Java 9 起已废弃，改用：
MyClass obj1 = MyClass.class.getDeclaredConstructor().newInstance();        // 无参构造
MyClass obj2 = MyClass.class.getDeclaredConstructor(String.class)           // 带参构造
                        .newInstance("world");
```

## 3. 调用方法（含传参、返回值、私有方法）

```java
Method greet = MyClass.class.getDeclaredMethod("greet", String.class);
Object result = greet.invoke(obj1, "world");   // 传参：参数跟在实例后面
System.out.println(result);                    // hello, world

// 私有方法：先放开访问权限
Method secret = MyClass.class.getDeclaredMethod("secret");
secret.setAccessible(true);
secret.invoke(obj1);
```

要点：

- `getMethod` 只找 **public**（含继承的），`getDeclaredMethod` 找**本类声明**的（含 private）；
- `invoke` 抛出的 `InvocationTargetException` 是**包装**——目标方法本身的异常在 `getCause()` 里；
- `setAccessible(true)` 是穿透 `private` 的关键，也是反射"破坏封装"的体现。

## 4. 读写字段

```java
Field name = MyClass.class.getDeclaredField("name");
name.setAccessible(true);

Object old = name.get(obj1);        // 读："hello"
name.set(obj1, "hi");               // 写

Field count = MyClass.class.getDeclaredField("count");
count.setAccessible(true);
count.set(null, 100);               // 静态字段：实例参数传 null 即可
```

## 5. 数组

数组没有构造器，用 `java.lang.reflect.Array` 统一处理：

```java
Object arr = Array.newInstance(int.class, 5);   // 等价于 new int[5]
Array.set(arr, 0, 42);
int v = (int) Array.get(arr, 0);                // 42
int len = Array.getLength(arr);                 // 5
```

## 6. 泛型：反射 + 类型擦除

运行期泛型已被擦除，但**签名里的泛型**可以通过 `ParameterizedType` 拿到：

```java
class Repo { public List<String> findAll() { return null; } }

Method m = Repo.class.getMethod("findAll");
Type t = m.getGenericReturnType();
if (t instanceof ParameterizedType pt) {
    System.out.println(pt.getRawType());          // interface java.util.List
    System.out.println(pt.getActualTypeArguments()[0]); // class java.lang.String
}
```

这也是 MyBatis / Jackson 能把 JSON 反序列化成 `List<User>` 的原理。

## 7. 访问控制与模块化（JDK9+）

`setAccessible(true)` 在遇到被**模块系统封装**的内部类（如 `java.base` 里的包）时会抛 `InaccessibleObjectException`，此时用 `trySetAccessible()`（失败返回 `false` 而非抛异常），启动参数可加 `--add-opens java.base/java.lang=ALL-UNNAMED` 打开。

## 8. 常用 API 速查

| 需求 | API |
|---|---|
| 拿 Class | `X.class` / `obj.getClass()` / `Class.forName(...)` |
| 构造器 | `getDeclaredConstructor(参数类型...)` |
| 方法 | `getDeclaredMethod(name, 参数类型...)` |
| 字段 | `getDeclaredField(name)` |
| 调用 / 读写 | `method.invoke` / `field.get` / `field.set` |
| 放开权限 | `setAccessible(true)` |
| 判注解 | `isAnnotationPresent` / `getAnnotation` |
| 修饰符 | `Modifier.isPublic(...)` |

# Spring 中的反射：优点是它，缺点也是它

## Spring 到底用反射做了什么

| 环节 | 反射动作 |
|---|---|
| 组件扫描 | 扫 classpath 上的 `.class`，读 `@Component`，为每个类建 `BeanDefinition` |
| 实例化 Bean | `constructor.newInstance(args)`（`BeanUtils.instantiateClass`） |
| 依赖注入 | `field.set(bean, dep)` / `method.invoke(bean, args)` |
| `@PostConstruct` / `@PreDestroy` | 反射查生命周期方法并 `invoke` |
| `@ConfigurationProperties` | 反射读写字段做属性绑定 |
| AOP | JDK 动态代理（`InvocationHandler` + `Method.invoke`）或 CGLIB 生成子类 |
| MVC | 反射绑定请求参数、调用 controller 方法、序列化返回值 |

一个"极简版 IoC"足以看清机制（把 `@Component` + `@Autowired` 换成自己的注解就是完整的迷你容器）：

```java
public class MiniContext {
    private final Map<Class<?>, Object> beans = new HashMap<>();

    public void start(String basePackage) throws Exception {
        // 1. 扫描：反射建实例（step 省略：遍历 classpath 得到所有类）
        for (Class<?> clazz : scanClasses(basePackage)) {
            if (clazz.isAnnotationPresent(Component.class)) {
                beans.put(clazz, clazz.getDeclaredConstructor().newInstance());
            }
        }
        // 2. 注入：反射给 @Autowired 字段赋值
        for (Object bean : beans.values()) {
            for (Field f : bean.getClass().getDeclaredFields()) {
                if (f.isAnnotationPresent(Autowired.class)) {
                    f.setAccessible(true);
                    f.set(bean, beans.get(f.getType()));   // 就是这一行赋值
                }
            }
        }
    }
}
```

## 优点

- **通用**：框架无法在编译期知道用户的类，反射是唯一能"运行时统一处理任意类型"的手段；
- **声明式**：一个 `@Autowired` / `@Transactional` 替代大量样板和 XML，靠的就是"读注解 → 反射执行"；
- **解耦与可扩展**：新增 Bean 只需加注解，容器逻辑不用改；
- **AOP 的地基**：动态代理能在不改源码的前提下织入增强。

## 缺点

- **性能**：反射调用比直接调用慢——多出方法查找、参数装箱、访问检查。**但**缓存 `Method`/`Field` 后差距大幅缩小，多数场景不是瓶颈；
- **丢失编译期类型安全**：类名、方法名写成字符串，错了要**运行时**才炸；
- **可读性 / 调试差**：调用链藏在框架内部，异常栈里全是 `invoke`，报错信息绕；
- **破坏封装**：`setAccessible` 能穿透 `private`，JDK9 模块化后还常被 `InaccessibleObjectException` 挡住；
- **对 GraalVM 原生镜像不友好**：AOT 编译看不到运行期反射，需要额外提供 `reflect-config.json`；
- **安全隐患**：绕过访问控制可能被滥用（反序列化漏洞常与之相关）。

# 权衡与实践

- **框架层用，业务层慎用**：反射是给通用框架写的，业务代码里有明确类型就别反射；
- **缓存**：`Method`/`Field`/`Constructor` 只查一次，存起来复用（Spring、Jackson 都这么干）；
- **追求性能时升级手段**：`MethodHandle`（`MethodHandles.Lookup`）比 `Method.invoke` 快，字节码生成（`LambdaMetafactory` / `ASM`）更快；
- **能生成代码就别运行期反射**：编译期用 APT（MapStruct、Lombok）把反射操作变成直调，兼得灵活与性能。

小结一句：**反射的优点是"通用"，代价是"性能和类型安全"**。对性能敏感的路径慎用；必须用时缓存元数据；能用编译期代码生成替代就替代。

对比一下直接调用与反射：

| | 直接调用 | 反射调用 |
|---|---|---|
| 性能 | 高 | 较低（可缓存缓解） |
| 类型安全 | 编译期检查 | 运行期才暴露 |
| 灵活性 | 编译期绑定 | 运行时动态决定 |
| 可读性 | 好 | 差、难调试 |
| 典型场景 | 业务代码 | 框架 / 通用逻辑 |

# 小结

1. **反射的入口是什么？** `java.lang.Class` 对象。三种获取方式：`X.class`、`obj.getClass()`、`Class.forName("全限定名")`。
2. **`forName` 和 `loadClass` 区别？** `Class.forName` 触发静态初始化（执行 static 块），`ClassLoader.loadClass` 不触发。
3. **`getMethod` 和 `getDeclaredMethod` 区别？** 前者只拿 public（含继承），后者拿本类声明的（含 private）。
4. **`newInstance()` 为什么废弃？** 只能调无参构造且异常处理不清晰；改用 `getDeclaredConstructor(...).newInstance(...)`。
5. **`invoke` 时目标方法抛异常，调用方拿到什么？** 被包成 `InvocationTargetException`，真实异常在 `getCause()`。
6. **`setAccessible(true)` 作用？** 关闭访问检查，可穿透 private。JDK9+ 模块封装下可能抛 `InaccessibleObjectException`，用 `trySetAccessible()` 或 `--add-opens`。
7. **反射为什么慢？怎么优化？** 方法查找、参数装箱、访问检查有开销；缓存 `Method`/`Field`，或用 `MethodHandle`/`LambdaMetafactory`。
8. **反射能拿到泛型吗？** 运行期泛型已擦除，但方法/字段**签名**里的泛型可用 `ParameterizedType` 取到。
9. **JDK 动态代理和 CGLIB 区别？** JDK 代理基于接口（`InvocationHandler`），CGLIB 生成子类（基于继承，不能代理 final）。
10. **反射和注解什么关系？** 注解是"声明"，反射是"读取并执行"，二者配合才有 Spring 的依赖注入/AOP。
