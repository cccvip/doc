注解（Annotation）天天用，但"什么是元注解""保留策略有哪几种""运行期为什么读不到"，很多人是模糊的。这篇从 `@interface` 一路讲到字节码，把注解这件事说透。

# 总览

注解是 JDK5 引入的一种**元数据**：它本身不改变程序逻辑，只是给类、方法、字段、参数等程序元素"贴标签"。标签只有在**编译期**（注解处理器 APT）或**运行期**（反射）被读取时，才会真正起作用。

一句话记住三件事：

1. 用 `@interface` 声明，本质是一个隐式继承 `java.lang.annotation.Annotation` 的接口；
2. 注解不配"读取逻辑"就是废纸，作用全靠反射或 APT；
3. 只有 `@Retention(RetentionPolicy.RUNTIME)` 的注解，运行时反射才看得到。

注解可以贴在类、方法、字段、参数、构造器、局部变量、包、类型参数等元素上，具体能贴哪儿由 `@Target` 决定。

# 元注解（注解的注解）

用来修饰"自定义注解"本身的注解，共 5 个：

| 元注解 | 作用 |
|---|---|
| `@Retention` | 保留到什么时候：`SOURCE` / `CLASS` / `RUNTIME` |
| `@Target` | 能贴在哪些元素上，取值是 `ElementType` 枚举 |
| `@Documented` | 生成 javadoc 时把这个注解带上 |
| `@Inherited` | 类级注解可被**子类**继承（只对 `class` 有效，接口/方法无效） |
| `@Repeatable` | 允许同一元素上重复贴同一个注解（Java 8+） |

## @Retention：三种保留策略

| 策略 | 保存在哪 | 运行时可见 | 典型例子 |
|---|---|---|---|
| `SOURCE` | 源码，编译后丢弃 | 否 | `@Override`、`@SuppressWarnings` |
| `CLASS`（**默认**） | 编译进 `.class`，但 JVM 不加载 | 否 | `@Deprecated` 的声明 |
| `RUNTIME` | 编译进 `.class`，JVM 加载 | **是** | `@Autowired`、`@Test` |

注意：**不写 `@Retention` 默认就是 `CLASS`**，运行时 `getAnnotation()` 会直接返回 `null`。所以只要打算用反射读，就必须显式写 `@Retention(RetentionPolicy.RUNTIME)`，别省。

## @Target：能贴在哪

常用取值（`ElementType`）：`TYPE`（类/接口/枚举）、`FIELD`、`METHOD`、`PARAMETER`、`CONSTRUCTOR`、`LOCAL_VARIABLE`、`ANNOTATION_TYPE`、`PACKAGE`，Java 8 起还有 `TYPE_PARAMETER`、`TYPE_USE`。

不写 `@Target` 表示**任何位置都能贴**。

# 内置注解

JDK 自带的常用注解：

- `@Override`：声明重写父类/接口方法，签名不匹配时编译报错（`SOURCE`）；
- `@Deprecated`：标记已过时，调用处给出警告；
- `@SuppressWarnings`：抑制指定类型的编译警告，如 `@SuppressWarnings("unchecked")`；
- `@FunctionalInterface`：声明函数式接口，多于一个抽象方法就报错；
- `@SafeVarargs`：声明可变参数泛型方法的类型安全，抑制堆污染警告。

# 自定义注解

## 声明

```java
import java.lang.annotation.*;

@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.TYPE, ElementType.METHOD, ElementType.FIELD, ElementType.PARAMETER})
public @interface MyAnnotation {
    String value() default "";   // 成员方法，长得像方法，其实是"属性"
    int number() default 0;
}
```

要点：

- 成员用**无参方法**形式声明，可带 `default` 默认值；
- 成员类型只能是：**基本类型、String、Class、枚举、其它注解，以及它们的数组**（不能是包装类/普通对象）；
- 名字叫 `value()` 的成员是特殊的：使用时若只给它赋值，可以省略 `value =`；
- 没写默认值的成员，使用注解时**必须**赋值。

## 应用

```java
@MyAnnotation(value = "example", number = 1)
public class MyClass {
    @MyAnnotation("on-field")            // value 可省略 key
    private String name;
}
```

## 反射读取

```java
Class<?> clazz = MyClass.class;

// 类上的注解
MyAnnotation ann = clazz.getAnnotation(MyAnnotation.class);
if (ann != null) {
    String value = ann.value();
    int number = ann.number();
    System.out.println(value + ", " + number);
}

// 字段 / 方法 / 参数上同样可以取
Field field = clazz.getDeclaredField("name");
MyAnnotation onField = field.getAnnotation(MyAnnotation.class);

Method method = clazz.getDeclaredMethod("foo", String.class);
MyAnnotation onMethod = method.getAnnotation(MyAnnotation.class);
MyAnnotation onParam  = method.getParameters()[0].getAnnotation(MyAnnotation.class);

// 是否存在
boolean present = clazz.isAnnotationPresent(MyAnnotation.class);
```

> 上例里的 `MyClass` 只是一个普通类；`getAnnotation` 能不能读到，取决于注解的 `@Retention` 是否为 `RUNTIME`——这正是前面反复强调的点。

`@Inherited` 相关 API 的差异：`getAnnotations()` 会**包含**从父类继承来的类级注解，`getDeclaredAnnotations()` 只看本类自己声明的。

## 重复注解

Java 8 之前一个位置只能贴一个同类型注解；`@Repeatable` 通过"容器注解"实现重复：

```java
@Retention(RetentionPolicy.RUNTIME)
@Repeatable(Schedules.class)
public @interface Schedule { String day(); }

@Retention(RetentionPolicy.RUNTIME)
public @interface Schedules { Schedule[] value(); }   // 容器，成员名必须是 value
```

```java
@Schedule(day = "Mon")
@Schedule(day = "Wed")
public class Task {}
```

读取时用 `getAnnotationsByType(Schedule.class)` 拿到 `Schedule[]`（`getAnnotation` 拿不到单个）。

# 运行原理与字节码

- 编译后，注解被记录为 class 文件里的 `RuntimeVisibleAnnotations`（RUNTIME）或 `RuntimeInvisibleAnnotations`（CLASS）属性；
- 反射读到的注解对象不是原类型实例，而是 JDK 用 `java.lang.reflect.Proxy` 动态生成的**代理**，方法调用转发给 `AnnotationInvocationHandler`，数据存在内部的 `memberValues` map 里；
- 所以运行期反射读注解有开销：第一次解析后会被缓存，但注解方法每次调用仍走代理，热路径上别反复反射。

## 注解处理器（APT）

如果注解在**编译期**就要发挥作用，靠的是 APT，而不是反射。实现一个继承 `AbstractProcessor` 的类，用 `@SupportedAnnotationTypes` 声明关心哪些注解，编译时 javac 会回调它。常见产物：

- **Lombok**：生成 getter/setter/构造器；
- **MapStruct**：生成对象映射代码；
- **Dagger**：生成依赖注入代码。

一句话区分：**编译期处理（APT）用来"生成代码"，运行期处理（反射）用来"读取信息"**。

# Spring 中的注解

Spring 的两大基础能力——**组件扫描**和**依赖注入**——都建立在注解 + 反射之上。

## 组件类注解：@Component 及其派生

`@Component` 是根，下面这些都是被它**元标注**的"组合注解"（派生注解），扫描时会被当作 `@Component` 处理：

| 注解 | 用途 |
|---|---|
| `@Component` | 通用组件 |
| `@Controller` | MVC 控制器 |
| `@Service` | 业务逻辑层 |
| `@Repository` | 数据访问层，额外把持久层异常转换成 Spring 统一异常 |

理解这一点比背列表更重要：`@Service` / `@Controller` / `@Repository` 只是语义化的 `@Component`。

## 依赖注入相关

- `@Autowired`：按类型自动装配，可用于字段、构造器、Setter、参数（实现类是 `AutowiredAnnotationBeanPostProcessor`，详见 [Spring依赖注入.md](../spring/Spring依赖注入.md)）；
- `@Qualifier`：配合 `@Autowired`，同类型多 Bean 时按名字选；
- `@Value`：注入配置值 / SpEL 表达式；
- `@ConfigurationProperties`：按前缀批量绑定配置。

## 配置与 MVC 相关

- `@Configuration`：配置类；`@Bean` 标注的方法返回值注册为 Bean（`@Configuration` 默认 CGLIB 代理，保证 Bean 是单例）；
- `@ComponentScan`、`@Import`、`@Conditional`：控制扫描范围、导入类、条件装配；
- `@SpringBootApplication` = `@SpringBootConfiguration` + `@EnableAutoConfiguration` + `@ComponentScan`（**组合注解**的典型）；
- `@RequestMapping` / `@GetMapping` / `@PostMapping`：请求路径映射；
- `@PathVariable`、`@RequestParam`、`@RequestBody`、`@ResponseBody`：参数与响应绑定；
- `@RestController` = `@Controller` + `@ResponseBody`（也是组合注解）；
- `@Transactional`：声明式事务，底层靠 AOP 代理。

# 小结

1. **注解有哪些保留策略？** SOURCE（源码，如 @Override）、CLASS（默认，字节码里但运行时不可见）、RUNTIME（可反射读取）。
2. **元注解有哪 5 个？** @Retention、@Target、@Documented、@Inherited、@Repeatable。
3. **不写 @Retention 会怎样？** 默认 CLASS，`getAnnotation()` 返回 `null`。
4. **注解成员能是什么类型？** 基本类型、String、Class、枚举、注解及其数组。
5. **@Inherited 的局限？** 只对类级注解生效；子类 `getAnnotations()` 能看到，接口实现、方法覆盖都不会继承。
6. **注解在字节码里怎么存的？** `RuntimeVisibleAnnotations` / `RuntimeInvisibleAnnotations` 属性。
7. **运行期读注解为什么有开销？** 注解对象是动态代理，方法调用经 `AnnotationInvocationHandler`。
8. **注解和 AOP 的关系？** Spring 先反射读注解拿到元数据，再据此生成代理织入增强（如 `@Transactional`）。
9. **@Repeatable 的原理？** 编译器把它编译成容器注解，读取时用 `getAnnotationsByType`。
10. **@Service 和 @Component 有区别吗？** 功能上都是组件，`@Service` 只是 `@Component` 的语义化派生，`@Repository` 额外做异常转换。
