# 一条主线

把 Spring 的核心流程压成一条线，就是：

```text
读取配置 → BeanDefinition → 实例化 → 属性填充(@Autowired) → 初始化(前后置扩展点) → 代理(AOP) → 放入单例池
```

围绕这条线，散布着几个关键扩展点：

| 阶段 | 扩展点 | 它在做什么 |
|---|---|---|
| 启动、Bean 实例化前 | `BeanFactoryPostProcessor` | 修改 BeanDefinition（图纸） |
| Bean 初始化前后 | `BeanPostProcessor` | 修改 Bean 实例；AOP 代理在此生成 |
| 属性注入 | `InstantiationAwareBeanPostProcessor` / `@Autowired` | 把依赖塞进字段/方法 |
| 初始化 | `InitializingBean` / `@PostConstruct` | 自定义初始化逻辑 |
| 销毁 | `DisposableBean` / `@PreDestroy` | 释放资源 |

# 高频问题速查

每条只给结论，细节点进对应分篇。

- **`FactoryBean` 是如何注册、管理对象的？** 它是一个编程契约（接口），不是靠反射或事件驱动；实现 `getObject()` 返回真正的对象。典型用途见 [SpringIOC.md](SpringIOC.md)，参考 MyBatis 的 Mapper 注册。
- **`BeanPostProcessor` 的作用？** 在 Bean 初始化前后做自定义处理，AOP 代理就在 `postProcessAfterInitialization` 里生成。详见 [基本概念.md](基本概念.md)。
- **`@Autowired` 是怎么拿到 Bean 的？** 先按类型找，多个同类型再按 `@Qualifier` / 字段名。详见 [Spring依赖注入.md](Spring依赖注入.md)。
- **`BeanFactoryPostProcessor` 做什么？** 在 Bean 实例化前修改 BeanDefinition。
