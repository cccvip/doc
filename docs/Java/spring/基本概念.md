Spring 源码里翻来覆去就那几类接口。这一篇不求深入，先把它们认全、混个眼熟——后面每篇用到时再回来看一眼就行。

> 看源码遇到"接口套接口、弯弯绕绕"的时候，记住一个技巧：**直接去看 `DefaultListableBeanFactory`**，它是很多接口的默认实现，往往一眼就能找到实现内容。

# BeanDefinition

BeanDefinition 是 Spring 里对"一个 Bean 的定义"的抽象：类型、作用域、依赖、属性值、初始化/销毁方法等，都记在这里。

```java
/**
 * BeanDefinition 描述了 bean 实例的属性值、构造方法参数等信息。
 * 它是一个最小接口——主要目的是允许 BeanFactoryPostProcessor
 * 去查看和修改 Bean 的属性及元数据。
 */
public interface BeanDefinition extends AttributeAccessor, BeanMetadataElement {
    String SCOPE_SINGLETON = ConfigurableBeanFactory.SCOPE_SINGLETON;
    String SCOPE_PROTOTYPE = ConfigurableBeanFactory.SCOPE_PROTOTYPE;

    String getScope();                          // 作用域：singleton / prototype ...
    void setDependsOn(@Nullable String... dependsOn);   // 依赖关系
    ConstructorArgumentValues getConstructorArgumentValues();   // 构造参数
    boolean isAutowireCandidate();              // 是否参与自动装配
}
```

几个常提到的属性：

- `class`：Bean 的类型；
- `scope`：作用域（单例 / 原型）；
- `lazyInit`：是否懒加载。

# BeanDefinitionReader

负责**扫描** BeanDefinition 并注册到 BeanFactory：

```java
public interface BeanDefinitionReader {
    int loadBeanDefinitions(Resource resource) throws BeanDefinitionStoreException;
}
```

常见实现：

- **`AnnotatedBeanDefinitionReader`**：SpringBoot 的注解扫描入口，处理 `@Conditional`、`@Scope`、`@Lazy`、`@Primary`、`@DependsOn`、`@Role`、`@Description` 等；
- **`XmlBeanDefinitionReader`**：解析 `Spring.xml` 生成 BeanDefinition。

# BeanFactory 与 ApplicationContext

`BeanFactory` 是最基础的容器接口，最重要的实现是 `DefaultListableBeanFactory`。

```java
public interface BeanFactory {
    Object getBean(String name) throws BeansException;
    <T> T getBean(Class<T> requiredType) throws BeansException;
    boolean containsBean(String name);
    boolean isSingleton(String name);
}
```

`ApplicationContext` 也是接口，但比 `BeanFactory` 更易用（多了事件、国际化、资源加载等能力），业务里更常注入它：

```java
@Service
public class StudentService implements ApplicationContextAware {
    private ApplicationContext applicationContext;

    @Override
    public void setApplicationContext(ApplicationContext applicationContext) throws BeansException {
        this.applicationContext = applicationContext;
    }

    @Resource
    StudentV2Mapper studentV2Mapper;
}
```

# BeanPostProcessor

一个 **BeanPostProcessor** 可以干涉**任意 Bean 的初始化前后**（注意是"初始化"不是"实例化"），是 Spring 最重要的扩展点之一。

```java
public interface BeanPostProcessor {
    // 初始化前
    @Nullable
    default Object postProcessBeforeInitialization(Object bean, String beanName) throws BeansException {
        return bean;
    }
    // 初始化后
    @Nullable
    default Object postProcessAfterInitialization(Object bean, String beanName) throws BeansException {
        return bean;
    }
}
```

AOP 代理就是在 `postProcessAfterInitialization` 里生成的（见 [SpringAop代理.md](SpringAop代理.md)）。什么时候被调用，见 [Spring生命周期.md](Spring生命周期.md)。

# BeanFactoryPostProcessor

它作用于**Bean 实例化之前**，用来修改 BeanDefinition（此时 BeanDefinition 已加载完成，但 Bean 还没建）。

```java
public interface BeanFactoryPostProcessor {
    // 可对 BeanDefinition 增删改，甚至 eager 初始化前就覆写/追加属性
    void postProcessBeanFactory(ConfigurableListableBeanFactory beanFactory) throws BeansException;
}
```

> 一句话区分：`BeanFactoryPostProcessor` 改的是 **BeanDefinition（图纸）**，`BeanPostProcessor` 改的是 **Bean 实例（产品）**。

# 小结

1. **BeanDefinition**：Bean 的"定义/图纸"，BeanFactoryPostProcessor 可改它。
2. **BeanDefinitionReader**：把定义**读进来**并注册，注解版是 `AnnotatedBeanDefinitionReader`。
3. **BeanFactory / ApplicationContext**：容器本体；后者功能更全，业务里更常用。
4. **BeanPostProcessor**：Bean **初始化前后**的扩展点（AOP 代理在此生成）。
5. **BeanFactoryPostProcessor**：Bean **实例化之前**，改 BeanDefinition。
